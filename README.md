# RAG-Based AI Teaching Assistant
IEEE Published Research | Kaggle Top 10% | GATE 2025

Ask a question about lecture videos and get a short answer that points to the exact video and minute to watch. It uses hybrid retrieval (dense + keyword), a cross-encoder reranker, a confidence gate that refuses questions the course does not cover, and a local LLM (LLaMA 3.2 through Ollama).

**Demo video:** _(add link)_

## What it does
- Turns lecture videos into searchable passages (Whisper speech-to-text, then passages of about 60 words with timestamps).
- Answers in 2 to 4 sentences and names the video, title and minute to watch, with the source passages shown below the answer.
- Says "the course does not seem to cover this" when the best passage is not relevant enough, instead of making something up.
- Everything runs locally (Ollama, FAISS, BM25); no paid API is needed.

## Data
18 lectures from the CodeWithHarry Sigma Web Development course (about 4.2 hours), transcribed with Whisper large-v2 (Hindi to English). That gives 7,252 transcript segments, which are merged into 1,222 overlapping passages of about 60 words. The lectures and their content belong to their creator; the transcripts here are used only to demonstrate the system.

## Architecture

```
Lecture videos -> FFmpeg audio -> Whisper large-v2 (Hindi -> English text with timestamps)
        |
7,252 short segments -> merged into 1,222 passages (~60 words, 20-word overlap)
        |
BGE-M3 embeddings (1024-dim) via Ollama
        |
   +----------------+----------------+
   |                                 |
FAISS IVF-Flat dense search    BM25 keyword search
   |                                 |
   +----------------+----------------+
                     |
       Reciprocal Rank Fusion (merges both ranked lists)
                     |
       Cross-encoder reranking (ms-marco-MiniLM-L-6-v2)
                     |
       Confidence gate: best reranker score below -7.44 -> "not covered"
                     |
           LLaMA 3.2 (via Ollama) writes the answer
                     |
        Answer + video + minute + source passages
```

## Results

Everything below was measured on 1,000 paraphrased questions generated by llama3.2 from random transcript segments (seed 42; `eval_questions.json` is included, so the numbers can be reproduced). A "strict hit" means the passage that contains the source segment is in the top 5.

### 1. Retrieval quality (passages of about 60 words)

| Setup | Recall@1 | Recall@5 | MRR@5 | Recall@5 incl. neighbours |
|---|---|---|---|---|
| Dense only (FAISS) | 33.0% | 54.7% | 0.411 | 56.1% |
| Keyword only (BM25) | 22.7% | 38.8% | 0.281 | 40.4% |
| Hybrid (FAISS + BM25 + RRF) | 31.7% | 55.7% | 0.401 | 57.1% |
| **Full pipeline (hybrid + rerank)** | **40.9%** | **64.0%** | **0.495** | **64.8%** |

The reranker is the largest gain (+8 points Recall@5 over hybrid). On the clearer questions (those that do not say "the author" or "this example", n=839) the full pipeline reaches 66.5% against 57.2% for dense only. The right *lecture* is among the top 5 results for 78.7% of questions (dense only: 73.0%); with only 18 lectures this is easier than it will be on a larger course.

### 2. What I found about chunking

The original chunks were single Whisper segments (median 6 words). On those, hybrid search was *worse* than dense search, and keyword search was weak because short chunks give BM25 almost nothing to match:

| Setup | Recall@5, 6-word segments | Recall@5, 60-word passages |
|---|---|---|
| Dense only | 50.8% | 54.7% |
| Keyword only | 26.0% | 38.8% |
| Hybrid | 49.1% | 55.7% |
| Full pipeline | 57.2% | 64.0% |

Merging into passages helped every setup and made hybrid better than dense. Caveat: a passage is a bigger target than a segment, so the strict numbers are not fully like-for-like. The fairer comparison, counting neighbouring segments as hits, goes from 59.9% to 64.8% for the full pipeline (about 5 points).

### 3. Failure analysis

The full pipeline missed 360 of 1,000 questions. Reading examples by hand (see `failure_cases_merged.md`) shows that many misses are not real failures:
- The question was generated from a **filler segment** with no content ("we will see all these things in the coming videos"), so no search could find it.
- The topic is **repeated in the same lecture**, and the retrieved passage is just as good as the expected one.
- The question is **vague** ("the author", "this example"), and the topic appears in several videos.

So 64.0% is a conservative figure. A cleaner test set of hand-written questions is future work.

### 4. Answer quality and refusing off-topic questions

Checked on 50 in-course and 15 out-of-course questions (`evaluate_answers.py`):

| Check | Result | Measured by |
|---|---|---|
| Answer cites a video that was actually retrieved | 94% (47/50) | text check |
| Answer supported by retrieved text | 58% (29/50) | llama3.2 as judge (indicative only) |
| Off-topic questions refused, prompt only | 40% (6/15) | llama3.2 as judge |
| **Off-topic questions refused, with confidence gate** | **80% (12/15)** | llama3.2 as judge |
| Median time per answer (retrieval + generation, Colab T4) | 1.3 to 1.5 s | measured |

The confidence gate refuses when the best reranker score is below -7.44. The threshold was chosen as the 5th percentile of top scores on 200 in-course questions, so about 95% of in-course questions still get an answer. On separate off-topic sets it refused 85% (20 questions) and 87% (15 questions) by score alone. These off-topic sets are small, and about 5% of real in-course questions would be refused by mistake.

### 5. Speed
FAISS IVF-Flat is **57x faster** than brute-force cosine search on the same data (11.95 ms to 0.21 ms per query on the original 7,252 vectors).

## Known limits
- Only 18 lectures; one course and one speaker.
- Test questions are LLM-generated, and some are poor (see failure analysis).
- The LLM judge in the answer check is the same small model that writes the answers.
- LLaMA 3.2 (3B) sometimes gives generic answers to vague questions.
- Retrieval sometimes returns the right topic from a different lecture.

## Tech stack
Whisper large-v2, BGE-M3 (Ollama), FAISS IVF-Flat, BM25 (rank_bm25), Reciprocal Rank Fusion, cross-encoder/ms-marco-MiniLM-L-6-v2 (sentence-transformers), LLaMA 3.2 (Ollama), FastAPI, LangChain, Docker, Python.

## Quick start
```bash
git clone https://github.com/Kaveri-Ghatage/rag-teaching-assistant.git
cd rag-teaching-assistant
pip install -r requirements.txt
ollama pull llama3.2
ollama pull bge-m3
# use the merged passages (recommended)
export EMBEDDINGS_FILE=embeddings_merged.joblib INDEX_FILE=faiss_index_merged.bin
uvicorn api:app --host 0.0.0.0 --port 8000     # open http://localhost:8000
```
Without the two environment variables the original per-segment index is used.

## Reproduce the evaluation
```bash
EMBEDDINGS_FILE=embeddings_merged.joblib INDEX_FILE=faiss_index_merged.bin python evaluate_retrieval.py --n 1000
python evaluate_retrieval.py --n 1000      # original short segments, same questions
EMBEDDINGS_FILE=embeddings_merged.joblib INDEX_FILE=faiss_index_merged.bin python evaluate_answers.py --n 50
```
